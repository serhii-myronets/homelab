# Add Sure finance dashboard on the Beelink

The owner chose a Sure trial to assess its Plaid-capable household-finance
dashboard. It runs locally at `https://sure.home`; there is no public route
until a deliberate design covers Plaid's callback requirements. Its four
containers share one pod: Postgres holds the records, Redis is only the
recreatable Sidekiq queue, and Rails web plus worker share attachment storage.
Postgres and attachments occupy directories of one 5 GiB LVM claim, which
VolSync snapshots and copies to R2 every hour at minute 40.

The first image reference used the Git release tag `v0.7.4`, but GHCR publishes
the matching image as `0.7.4`. The pod therefore reached `ImagePullBackOff`
until the reference was corrected. After initial migrations, Sure measured 704
MiB RAM and 29m CPU at idle; the Beelink node measured 70% RAM in use.

Sure's initial log said that Active Record encryption was absent, which would
leave future provider tokens unencrypted in Postgres. The first attempt to
parse `bin/rails db:encryption:init` treated its YAML output as assignment
lines and put empty values in Infisical. No account or provider had been
created, so fresh correctly parsed keys replaced them before use. The
ExternalSecret now supplies the primary, deterministic and derivation-salt
keys; a restarted pod no longer logged the warning. The database password and
Rails secret are also in Infisical under `/sure`.

No owner account, Plaid credentials, bank account or financial data was added
by automation.
